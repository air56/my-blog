# 文章 Markdown 渲染与布局修复设计

## 目标

修复 `wsl-astrbot-bangumi` 文章在线页面的 Markdown 渲染问题，使代码块、行内代码、列表、标题、引用、表格和分隔线使用合法、稳定的 HTML 结构，并保持现有文章内容与站点视觉风格。

## 当前问题

文章源文件中的 Markdown 代码围栏是正确的，但文章页使用多组正则表达式直接把 Markdown 转换为 HTML。这会导致：

- 围栏代码被当作普通文本，出现裸反引号和语言标识；
- 代码内容内部被插入 `<p>`，无法形成真正的代码块；
- 标题被段落标签包裹；
- 列表项可能脱离 `<ul>` 或 `<ol>`；
- 表格、引用和分隔线容易受到段落包装规则影响。

## 方案

新增独立的服务端 Markdown 渲染模块，使用 `marked` 解析文章正文。页面组件只负责调用渲染模块并注入解析结果，不再维护正则替换链。解析器配置使用 GitHub 风格换行、稳定的标题 ID，并保留文章中的代码语言标识，便于 CSS 展示。

文章源文件只做必要的内容审校：保留正常的中文标点和命令示例，不做全局删除“、”等字符，避免损伤正文语义。

## 视觉与布局

- 围栏代码输出为 `<pre><code class="language-...">`，使用现有深色代码块样式；
- 代码块启用横向滚动，长命令不撑破正文列；
- 行内代码与代码块保持不同视觉层级；
- 列表、引用、表格和标题使用现有文章间距体系；
- 不改变文章页整体宽度、侧栏和标签区域布局。

## 验证

增加 Markdown 渲染回归测试，覆盖代码块、行内代码、列表、标题、引用和表格，并明确断言不会生成代码块中的段落嵌套。完成后运行测试、ESLint 和 Next.js 静态构建，并检查生成 HTML 中不再存在异常的裸反引号或未闭合结构。
