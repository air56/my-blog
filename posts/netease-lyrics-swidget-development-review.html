从歌词条到桌面组件：网易云双语歌词小组件的开发复盘

从歌词条到桌面组件：网易云双语歌词小组件的开发复盘

最近为 Sapphire 开发了一个网易云音乐双语歌词小组件。它能够自动识别当前播放歌曲，获取网易云歌词，并以透明歌词层的形式显示原文、中文翻译和下一句歌词。

这次开发的重点并不只是“把歌词显示出来”，而是处理好播放同步、切歌状态、翻译布局、旧版 WebEngine 兼容和日常启动体验。

背景：为什么需要一个本机歌词组件

项目运行在 Windows 10/11 上，主要由两部分组成：

  • Sapphire HTML Widget：负责歌词显示、布局和设置；
  • 本机 Bridge：负责读取系统媒体信息、查询网易云歌词和向组件推送状态。

组件优先读取 Sapphire 提供的 SMTC/WebChannel 媒体信息；当 WebChannel 不可用时，再使用 Windows 系统媒体会话作为兜底。

Bridge 只监听本机地址：

http://127.0.0.1:18763

这样既能避免组件直接依赖外部服务，也不会把网易云登录凭据放进项目中。

第一阶段：先确定歌词组件的视觉结构

最初的设计目标是“液态玻璃”风格，但实现过程中发现，卡片背景、亚克力模糊、边框和环境光会让歌词组件在桌面上显得过重。

最终将正式组件调整为纯透明歌词层：

  • 不绘制卡片背景；
  • 不添加边框和亚克力材质；
  • 只保留轻微文字阴影；
  • 原文使用最高对比度；
  • 翻译和下一句使用较低透明度；
  • 通过自由宽高适配歌词条、窄屏和较高的组件布局。

这让歌词更像悬浮在桌面上的文字，而不是一个固定面板。

第二阶段：解决双语歌词的布局跳动

双语歌词最容易出现的问题是：某一句有翻译时占两行，没有翻译时只占一行，导致下一句歌词上下跳动。

因此渲染层采用固定高度的歌词槽位：

当前原文
当前翻译（没有翻译时保留空槽位）
下一句原文
下一句翻译

核心原则是：翻译内容可以隐藏，但不能改变当前歌词区域的几何高度。

同时，歌词展示逻辑还需要处理几个边界：

  • 翻译不存在时不显示空文本；
  • 超过最大长度时截断，但不能拆开代理对；
  • 播放开始前显示第一句作为预览；
  • 最后一行歌词不显示不存在的下一句；
  • 中英文使用独立的字体栈。

第三阶段：处理暂停、拖动和切歌

歌词同步不能只依赖歌词接口返回的时间戳，还必须正确处理播放状态。

播放状态主要包括：

  • Playing；
  • Paused；
  • Stopped；
  • 切歌；
  • 拖动进度；
  • 媒体信息延迟更新。

开发过程中遇到一个典型问题：暂停时，Sapphire 可能先报告正确的播放位置，随后又发出一个位置为 0 的暂停快照。如果直接采用最新数据，歌词位置就会突然重置到开头。

修复方式是在暂停状态下保留最近一次有效位置：

if (state === 'Paused' && positionMs === 0) {
  positionMs = lastKnownPositionMs;
}

恢复播放时，再从保留的位置继续推进。

切歌时则必须创建新的会话标识。旧歌曲的歌词请求、延迟回调和事件不能继续覆盖新歌曲：

新 trackSessionId
    ↓
清空旧歌词
    ↓
进入 loading 状态
    ↓
查询并匹配新歌词
    ↓
原子替换显示内容

这样可以避免切歌时短暂显示上一首歌歌词的问题。

第四阶段：增加 Bridge 推送和轮询双通道

Bridge 原本主要通过 SSE 推送状态，但实际运行时还要考虑：

  • SSE 连接中断；
  • Sapphire WebEngine 网络层行为差异；
  • Bridge 重启；
  • 浏览器端事件丢失。

因此组件增加了定时快照轮询作为兜底：

SSE 有更新 —— 立即处理
SSE 暂时不可用 —— 定时读取 /v1/snapshot
Bridge 恢复 —— 重新建立事件连接

轮询不会替代 SSE，而是用来保证歌词状态最终能够恢复。

第五阶段：兼容旧版 Sapphire WebEngine

Sapphire 的部分环境使用较老的 WebEngine，不能完全依赖现代浏览器能力。

为此，组件增加了经典脚本运行时：

  • 将模块化源码构建为兼容的 app.runtime.js；
  • 入口页面直接加载经典脚本；
  • 避免使用旧 WebEngine 不支持的 DOM 更新方式；
  • 生成运行时版本标记，配合组件版本号刷新缓存。

打包前会执行运行时生成脚本：

node .\scripts\build-widget-runtime.mjs

正式组件包由 PowerShell 脚本生成：

.\scripts\package-widget.ps1

输出文件类似：

dist/netease-lyrics-glass-v0.1.14.sawidget

第六阶段：把 Bridge 做成登录自启动

如果每次使用歌词组件都要手动启动 Bridge，实际体验会比较差。

因此增加了用户级任务计划自启动：

.\scripts\install-bridge-autostart.ps1

这个脚本会：

  • 创建当前用户的登录触发任务；
  • 隐藏窗口启动 Bridge；
  • 避免重复启动已有实例；
  • 将标准输出和错误输出保存到本地日志；
  • 不需要管理员权限。

对应的卸载命令是：

.\scripts\uninstall-bridge-autostart.ps1

Bridge 的日志位置：

%LocalAppData%\NeteaseLyricsBridge\bridge.stdout.log
%LocalAppData%\NeteaseLyricsBridge\bridge.stderr.log

测试和验证

本次开发采用了单元测试、契约测试和构建测试结合的方式。

前端和组件测试覆盖：

  • 双语歌词槽位；
  • 歌词截断；
  • 播放状态推进；
  • 暂停位置保留；
  • 纯透明样式；
  • 设置持久化；
  • WebChannel 数据解析；
  • Bridge 轮询兜底；
  • 自启动脚本；
  • Sapphire 旧版运行时兼容；
  • 打包元数据和缓存刷新。

执行命令：

node --test .\tests\*.test.mjs .\widgets\netease-lyrics-glass\tests\*.test.mjs

结果：

59 tests
59 passed
0 failed

Bridge 的 .NET 测试执行：

dotnet test .\NeteaseLyrics.sln --no-restore

结果：

通过：40
失败：0
跳过：0

开发过程中的几个经验

问题 修复方式 经验
翻译出现时下一句跳动 使用固定高度歌词槽位 视觉布局要先稳定，再处理内容变化
暂停后歌词回到开头 保留最近一次有效播放位置 媒体状态更新不能盲信单次快照
SSE 断开后歌词不更新 增加快照轮询兜底 实时推送和最终一致性需要同时考虑
旧版 WebEngine 无法运行模块脚本 生成经典脚本运行时 组件运行环境比普通浏览器更复杂
Bridge 每次都要手动启动 增加用户级登录自启动 本地工具的日常使用体验同样重要
切歌时短暂显示旧歌词 使用 trackSessionId 丢弃过期响应 异步请求必须绑定会话生命周期

总结

这个项目从一个简单的“歌词显示组件”，逐步扩展成了包含媒体识别、歌词匹配、双语渲染、播放同步、本机 Bridge、自动启动和兼容运行时的完整桌面小组件。

开发过程中最重要的收获是：桌面组件的难点通常不在单个功能，而在各种状态之间的衔接。播放暂停、切歌、网络失败、Bridge 重启和旧版运行环境，都需要在设计阶段提前考虑。

最终版本更强调稳定、低干扰和可恢复性——歌词直接悬浮在桌面上，同时在异常发生后能够自动恢复到正常状态。
